✳ Agent VillageSetup guide

Your own village

Start with Maya on your computer.

A learner can clone the project, use their own OpenAI or Anthropic API key, and build a small site with Maya. The hosted Preview needs separate owner setup before sign-in or paid runs work.

Keys stay on the server. Enter an API key in your ignored .env.local file or a silent terminal prompt. Never put it in this page, chat, a Git commit, or browser storage. API usage can be billed by your provider.
01

Start on your computer

You need Node.js 20.12 or newer and access to this repository. While the interface is in draft PR #30, clone its branch:

git clone --branch village-interface-20261011-01 --single-branch https://github.com/startupsandcode/agent-village.git
cd agent-village

Create an OpenAI API key in your OpenAI developer account. This is separate from a ChatGPT subscription. For Anthropic, create a key in your Anthropic Console instead.

Make a file named .env.local at the repository root, then run chmod 600 .env.local so only your account can read it. It is ignored by Git. Put only your own provider choice and key there:

VILLAGE_PROVIDER=openai
OPENAI_API_KEY=your-own-key-here

For Anthropic, use VILLAGE_PROVIDER=anthropic and ANTHROPIC_API_KEY. Keep this file private on your computer. An already exported shell variable takes precedence over the file.

node local/server.mjs

Open http://127.0.0.1:4174/. Name your office, answer the short domain interview, and describe a small website to Maya. The status line confirms only that a key is present; the first request verifies live access. If it says Missing OPENAI_API_KEY, check the filename, location, provider choice, and restart the server.

02

Publish a reviewed local site

After Maya, Sam, and Quinn finish, choose Prepare reviewed files. The interface then shows two separate publish actions. Neither action runs until you press its button and enter an exact target.

For GitHub, use an existing private repository with an existing branch other than its default branch. Put a fine-grained, single-repository token with Contents read/write in the local server’s .env.local as VILLAGE_PUBLISH_GITHUB_TOKEN. For Vercel, use an existing static project in your own team and add VILLAGE_PUBLISH_VERCEL_TOKEN to the local server environment. Give that token the narrowest available team scope. Restart the local server after changing the file.

The GitHub action commits the receipt-checked files to that branch. The Vercel action uploads the reviewed HTML and CSS to a Preview deployment and shows its actual state. It does not create accounts, repositories, projects, or a Production deployment. Check the target before each click; a Preview URL may be publicly reachable unless you configure deployment protection.

03

Configure the Village Office Preview

Preview sign-in uses Sign in with Vercel, not a Google OAuth integration in this app. A Google account may be one way you sign in to Vercel; it does not configure the office. A Preview that says “Private office sign-in is not configured” needs the app’s server-side auth settings.

  1. Create your own confidential OAuth app in Vercel Team Settings → Apps. Use client_secret_post and the openid and email scopes. Register the exact callback https://YOUR-PREVIEW-HOST/api/auth/callback.
  2. In the Vercel project’s Settings → Environment Variables, select Preview. Add VERCEL_APP_CLIENT_ID, VERCEL_APP_CLIENT_SECRET, a random OFFICE_SESSION_SECRET of at least 32 bytes, and OFFICE_ALLOWED_EMAILS with your invited email address.
  3. Add OFFICE_ALLOWED_ORIGINS=https://YOUR-PREVIEW-HOST with no path or trailing slash. It must match the Preview you open. Register every allowed origin’s callback in the OAuth app. Use secret/server-only settings for credential values.
  4. Redeploy that Preview so the new settings reach the server. Open /office again and sign in with an email on the invite list.

A branch-specific Preview host can change. Check the exact URL in Vercel before setting the allowed origin and callback. A configured sign-in permits viewing the office; it does not turn on Maya’s hosted build.

04

Enable a hosted test run only when ready

Use a new database dedicated to Agent Village for the hosted Preview. In that database’s SQL editor, run the complete contents of office/hosted/001_projects.sql once. Confirm that village_projects, village_monthly_budget, and village_budget_claims appear. Use an application database role limited to those tables where your database permits it. Keep the connection string in Preview server-side settings as VILLAGE_DATABASE_URL; do not paste it into this page or chat.

After running 001_projects.sql, run the additive office/hosted/002_usage.sql and office/hosted/003_domain_profiles.sql migrations in that order in the same database before enabling this version of hosted Maya. They create owner-scoped provider-call and domain-answer records without changing existing project or budget rows. See the SQL editor instructions. With only 001, the health check still reads the original tables, but the updated runtime gates all hosted project actions and reads until both migrations are ready.

After redeploying with the database URL and signing in as an allowed operator, open /api/maya-health on that same Preview. It reads the three original tables without starting Maya or using provider credits. ready: true confirms those reads; usageReady: true and domainReady: true confirm the new tables are readable. These checks do not prove write access or a live model key.

For a paid Preview test, also set OFFICE_RUN_ALLOWED_EMAILS to your own invited email, VILLAGE_PROVIDER=openai or anthropic, and the matching OPENAI_API_KEY or ANTHROPIC_API_KEY in Preview server-side settings. Set a provider spending limit. Only after the protected Preview sign-in, database schema, and key are ready, set VILLAGE_HOSTED_RUNS_ENABLED=true for Preview and redeploy.

The hosted office can show publish buttons after Quinn approves. For GitHub, configure VILLAGE_PUBLISH_GITHUB_TOKEN, VILLAGE_PUBLISH_GITHUB_OWNER, VILLAGE_PUBLISH_GITHUB_REPO, and VILLAGE_PUBLISH_GITHUB_BRANCH in Preview server-side settings. Use a fine-grained Contents read/write token limited to one new private repository with an existing non-default branch. Initialize that branch with a harmless file such as notes.txt, not any of the six delivery filenames. Check that the repository has no Pages, Actions, webhooks, or connected production deployment, then set VILLAGE_PUBLISH_GITHUB_DEDICATED_REPO_CONFIRMED=true. The app checks Pages and the branch’s .github directory; you must check external webhooks and integrations yourself.

For hosted Vercel Preview publishing, configure VILLAGE_PUBLISH_VERCEL_TOKEN, VILLAGE_PUBLISH_VERCEL_TEAM, and VILLAGE_PUBLISH_VERCEL_PROJECT in Preview server-side settings. Choose a separate existing static project with no Git link or custom build, install, output, or ignore settings; do not point it at the Agent Village office project. Scope the token to the intended team as narrowly as Vercel permits. These hosted settings are separate from a clone’s .env.local. No credentials are entered into the office page.

The current hosted run has only deterministic mock verification. A key being present does not prove provider or database access. A learner’s quickest first test is the local path above.

The usage panel tracks only API calls made by this Village. It does not show ChatGPT or Codex subscription quota. Provider-reported tokens are measured, while displayed costs are estimates using model rates checked on 2026-10-11. Pending, failed, or cancelled calls without reported usage may still be billed; check your provider dashboard for actual charges.
