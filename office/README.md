# Hosted Agent Village office

The Vercel `agent-village` project uses `office` as its Root Directory. It serves the [synthetic demo](https://agent-village.startupsandcode.com/) at `/` and the invited office at `/office`. `/api/office` is also private. Project-wide Vercel Authentication is disabled; the application enforces office access. The old `agent-village-demo` project has been deleted.

An anonymous visit to `/office` shows a minimal sign-in page. The viewer must choose **Sign in with Vercel** to start OAuth. **Sign out of office** clears the office session and returns to the demo; returning to `/office` shows the sign-in page even if the viewer is still signed in to Vercel. An uninvited account receives an access-denied response.

## Sign in with Vercel app

In Vercel Team Settings → Apps, create an app with confidential `client_secret_post` authentication. Register both exact callback URLs: `https://agent-village-six.vercel.app/api/auth/callback` and `https://agent-village.startupsandcode.com/api/auth/callback`. The server selects the callback from the registered production host. Enable only the `openid` and `email` scopes; the office does not request Vercel API permissions or offline access. A viewer must have a Vercel account and an email address on the office invite list.

Set these **server-only** environment variables in the existing project for Production (and for Preview if you will use a separately registered callback there):

| Variable | Value |
| --- | --- |
| `VERCEL_APP_CLIENT_ID` | ID shown on the Vercel app's Manage page |
| `VERCEL_APP_CLIENT_SECRET` | The generated confidential client secret |
| `OFFICE_SESSION_SECRET` | Independently generated random signing secret, at least 32 bytes; changing it signs everyone out |
| `OFFICE_ALLOWED_EMAILS` | Comma-separated, exact invited email addresses; compared without case on every private request |
| `GITHUB_AGENT_TOKEN` | Existing server-only GitHub token with Issues read access (`GITHUB_ISSUES_TOKEN` takes precedence when set) |

Do not prefix these variable names with `NEXT_PUBLIC_`, and do not place values in source files or `public/`. Redeploy after changing environment variables. A missing value denies access. Sign-in on unregistered Preview hosts fails closed. Register the Preview's exact callback in your Vercel OAuth app and set its exact HTTPS origin in Preview-scoped `OFFICE_ALLOWED_ORIGINS` before testing. The public `/setup` page walks through this configuration.

## A cloned office

Set `OFFICE_ALLOWED_ORIGINS` to a comma-separated list of **exact HTTPS origins** for your own Vercel host and custom domain, and register `<origin>/api/auth/callback` in your own confidential Vercel OAuth app. When this variable is set, John's default hosts are no longer allowed. Set `OFFICE_ALLOWED_EMAILS` to your own invited email list and generate your own `OFFICE_SESSION_SECRET`. Set `VILLAGE_GITHUB_REPO=your-owner/your-repo` and give the server a credential limited to reading that repository's issues. A cloned hosted office with its own origins but no repository setting shows an unavailable board; it does not fall back to John's issues. `office/.env.example` contains variable names and placeholders; enter real values only in your Vercel project's server-side secret settings. Do not copy John's OAuth app, allowlist, provider key, or issue token. If the issue credential is absent or does not match the repository, the board reports unavailable rather than showing another repository's tasks.

`/api/maya-status` uses the same office session guard as `/api/office`. It reports only whether a provider key is present, without returning or validating the key. The hosted coordinator and storage adapter are implemented, but the existing deployment has no activated database-backed run or verified live provider call. A user can use the local interface described in `local/README.md` now; setting a Vercel secret alone does not make a hosted run work.

The private office shows setup status for viewer sign-in, explicit provider-spending permission, provider key, durable project storage, future code execution, GitHub publishing and Vercel publishing. A provider key and database URL show as configured but unverified. The first hosted artifact is a static website rendered without executing model-written code; Vercel Sandbox is needed only for broader code tasks. `hosted/001_projects.sql` stores owner-scoped snapshots and monthly budget claims; apply the additive `hosted/002_usage.sql` and `hosted/003_domain_profiles.sql` before enabling this version of hosted Maya. The interview stores answers per signed-in owner and snapshots them into each new project for Maya, Sam, and Quinn. They are tested end-to-end with fake/in-memory adapters, including cross-owner denial, forged-state rejection, duplicate calls and cancellation. No live database or provider call has been tested; hosted runs remain disabled until the owner enables them. ### Minimal hosted setup proposal

The existing `jmanns-projects/agent-village` Vercel project already has Root Directory `office/`, Node 24, and the private viewer OAuth flow. Keep this project. For the first paid test, use a new database dedicated to Agent Village and connect it to Preview only. Do not reuse another product's database. In its SQL editor, run the complete `hosted/001_projects.sql`, `hosted/002_usage.sql`, and `hosted/003_domain_profiles.sql` files in order and confirm the five `village_` tables exist. Give the application a database role limited to those tables where supported. No Redis, Blob store, or Sandbox is needed for the bounded static-site path. The `office/` package locks `@neondatabase/serverless`; the runtime opens a per-request pool for parameterized queries and transaction-scoped budget claims, then closes it.

Use `VILLAGE_DATABASE_URL` for the dedicated database connection in **server-only Preview** settings. Keep `VERCEL_APP_CLIENT_ID`, `VERCEL_APP_CLIENT_SECRET`, `OFFICE_SESSION_SECRET`, `OFFICE_ALLOWED_EMAILS`, and exact `OFFICE_ALLOWED_ORIGINS` server-only in Preview too. Add `OFFICE_RUN_ALLOWED_EMAILS` for the smaller set of people allowed to incur provider charges; viewer access alone cannot run a project. Choose either `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` with `VILLAGE_PROVIDER`; a provider key is billed separately and should be project restricted and spend limited. The pilot accepts only `gpt-4.1-mini` or `claude-sonnet-5-5`, with at most 20 projects, 80 calls and $100 of conservative call reservations per signed-in owner (OAuth subject) per month. A call reservation is a budget allowance, not a measured provider bill. Do not put credentials in `public/`, browser storage, chat, logs, or Git. Hosted publishing uses separate Preview-scoped server credentials and destinations; local publish buttons use credentials in the local process.

The route is **off by default**. After provisioning, applying the schema, setting exact OAuth origins and an operator allowlist, and preparing a protected Preview, set `VILLAGE_HOSTED_RUNS_ENABLED=true` only there for a paid smoke test with your own key. Check the question, plan, artifact digest, cancellation and budget records before enabling Production. The status page reports configured key/database presence as unverified until a real request succeeds. This PR does not apply the migration, create an account, call a live provider, or publish a live site.

Hosted publishing uses the same signed-in owner and operator allowlist as hosted runs, exact same-origin POST checks, and a durable project snapshot claim before either external write. Configure the exact private GitHub owner/repository/non-default branch and a single-repository Contents read/write token with `VILLAGE_PUBLISH_GITHUB_*` Preview variables in `.env.example`. Set `VILLAGE_PUBLISH_GITHUB_DEDICATED_REPO_CONFIRMED=true` only after inspecting the separate repository for Actions, Pages, webhooks, and connected deployment systems. The adapter checks Pages and `.github` on the target branch, but external webhooks cannot be established with a Contents-only token. A repository can be initialized with `notes.txt`; do not seed it with a delivery filename. Configure the exact separate static Vercel project, team and team-scoped token with `VILLAGE_PUBLISH_VERCEL_*`. Vercel assigns a project's first deployment to Production even when the target is omitted, so the adapter refuses a project without an existing ready Production deployment. The adapter also rejects custom build settings and checks the returned deployment target. Tokens and target settings stay in the hosted server environment, not a learner's `.env.local` or browser. No repository, branch or Vercel project is created automatically. A durable `submitting` receipt blocks automatic retries when an external result is uncertain.

The pilot code caps hosted runs at 20 projects and 80 provider calls per month per signed-in owner. At the current 1,800 output-token and 32,768-byte input limits per call, 80 calls can emit at most 144,000 output tokens and send at most 2.62 million input bytes. Using [Anthropic's published Sonnet 5.5 rates](https://www.anthropic.com/claude-sonnet-5-5) of $10 per million output tokens and $2 per million input tokens, this is roughly $7 in model usage if input tokens are no more numerous than input bytes. Provider overhead, retries, database usage, Vercel Functions, and any other workloads add cost and need separate limits. Set a provider spend cap and Vercel spend management below the $300 monthly total budget before a paid test. These are planning estimates, not observed charges or a guarantee; no paid run occurred here.
